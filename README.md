# T-Work агент v3

Автономный агент для заданий на платформе T-Work: Playwright управляет браузером,
LLM (gpt-4o через ProxyAPI или OpenRouter) выбирает действия. Что изменено по сравнению
с v2 и почему — в [AUDIT.md](AUDIT.md).

## Что нужно заранее

- **Python 3.10–3.14** (проверено на 3.10, 3.11, 3.13, 3.14). Для Windows: при установке с python.org
  отметьте «Add python.exe to PATH».
- **Ключ API** ProxyAPI (или OpenRouter).
- Интернет для установки пакетов и браузера (≈150 МБ).

## Установка (один раз)

Все команды выполняются **в папке проекта** (там, где лежит `main.py`).
Команды для Windows даны для PowerShell или cmd; для macOS/Linux — отдельной строкой.
Если вы ставите пакеты без виртуального окружения (в общий Python), вместо
`.venv\Scripts\python` пишите просто `python`.

**1. Виртуальное окружение**

```
python -m venv .venv
```
(macOS/Linux: `python3 -m venv .venv`; если на Windows несколько версий Python — `py -3.11 -m venv .venv`)

**2. Пакеты**

```
.venv\Scripts\python -m pip install -r requirements-dev.txt
```
(macOS/Linux: `.venv/bin/python -m pip install -r requirements-dev.txt`)

`requirements-dev.txt` = пакеты агента + pytest для самопроверки. Без тестов хватит `requirements.txt`.

**3. Браузер для Playwright**

```
.venv\Scripts\python -m playwright install chromium
```
(macOS/Linux: `.venv/bin/python -m playwright install chromium`)

Если загрузка браузера не проходит, можно использовать уже установленный Google Chrome:
пропустите этот шаг и впишите в `.env` строку `BROWSER_CHANNEL=chrome`.

**4. Настройки**

```
copy .env.example .env
notepad .env
```
(macOS/Linux: `cp .env.example .env` и откройте `.env` в любом редакторе)

В `.env` проверьте две строки:

- `TARGET_URL=` — адрес страницы, с которой вы начинаете работу с заданиями. По умолчанию
  `https://twork.tbank.ru`; если вы начинаете с другой страницы — скопируйте её адрес из
  адресной строки браузера.
- `OPENAI_API_KEY=` — ключ ProxyAPI. Для режима записи (`--record`) он не нужен.

Остальное уже настроено:
ProxyAPI + `gpt-4o`, окно браузера видно (`HEADLESS=false`), логин сохраняется в папке
`.browser-profile` (`USER_DATA_DIR`). Для OpenRouter раскомментируйте две строки в `.env`
(`OPENAI_BASE_URL` и `LLM_MODEL=openai/gpt-4o`).

**5. Самопроверка (рекомендуется, ключ не тратится)**

```
.venv\Scripts\python -m pytest
```
(macOS/Linux: `.venv/bin/python -m pytest`)

Ожидаемый итог: `40 passed`. Тесты запускают браузер на локальных тестовых страницах и
проверяют парсер, клики, память и весь цикл агента — к T-Work и к LLM они не обращаются.

## Запуск

```
.venv\Scripts\python main.py
```
(macOS/Linux: `.venv/bin/python main.py`)

Что происходит при **первом** запуске:

1. Открывается окно Chromium на весь экран со страницей T-Work.
2. В логе раз в 30 секунд: `Целевой фрейм не найден — жду…`. Это нормально: агент ждёт до
   15 минут (`MAX_IDLE_SECONDS`).
3. В этом окне **войдите в аккаунт и откройте страницу с заданиями** так же, как делаете вручную.
4. Как только появится фрейм задания, агент начнёт работать: в логе появятся строки
   `Снимок #…`, `СМЕНА ЗАДАНИЯ`, `LLM решение`, `ВЫПОЛНЯЕМ`, `✅ ЗАДАНИЕ ОТПРАВЛЕНО`.
5. Пока агент работает, не кликайте в его окне.

Следующие запуски: вход уже сохранён в `.browser-profile`, агент сразу найдёт задания.

**Остановка:** `Ctrl+C` в терминале или закрыть окно браузера. Агент также останавливается сам
после `MAX_STEPS` шагов с действием (по умолчанию 80).

**Капча:** если появилась, решите её в окне браузера — агент ждёт до 10 минут.

## Режим записи (для настройки агента под новые виды заданий)

```
.venv\Scripts\python main.py --record
```
(macOS/Linux: `.venv/bin/python main.py --record`)

В этом режиме агент **ничего не нажимает** и ключ API не нужен. Вы проходите задания вручную
в открывшемся окне, а агент на каждом новом экране сохраняет:

- HTML страницы задания и скриншот окна;
- то, что он отправил бы модели на этом экране (`llm_view.txt`);
- ваши действия: клики, выбор вариантов, введённый текст, Enter;
- переходы в других вкладках (поиск в интернете) и скриншоты этих страниц.

В консоли видно, что запись идёт: `📸 #12 …` — новый экран, `👆 click …` — ваше действие.

Закончить запись: закройте окно браузера (или `Ctrl+C` в терминале). Всё упакуется в
`recordings\<дата-время>-part1.zip` (если данных много — несколько частей до 24 МБ).

**Как проходить задания во время записи**

- Важнее разнообразие, чем количество: в каждом виде задания/теста 2–3 задания, затем следующий вид.
- Показывайте и правильные решения, и ошибки — так видно, как платформа сообщает об ошибке.
  Намеренно ошибайтесь только там, где это безопасно: ошибки в квалификационных тестах
  могут снизить рейтинг или закрыть доступ к заданиям.
- Поиск в интернете делайте в новой вкладке **этого же окна** — тогда запишутся запросы
  и открытые страницы.
- Пояснения («здесь правильный ответ такой, потому что…») пишите текстом: в чат или в файл
  `notes.txt` рядом с архивом.

**Как отправить запись.** В архиве ваши данные (имя аккаунта, содержимое заданий), поэтому:

1. Сделайте репозиторий приватным: Settings → General → Danger Zone → Change visibility → Private.
2. На странице репозитория: Add file → Upload files → перетащите zip-части.
3. Внизу выберите «Create a new branch for this commit», назовите ветку `recordings` → Commit changes.

## Первый запуск — пробный

Для первого знакомства с реальной страницей поставьте в `.env`:

```
MAX_STEPS=10
LOG_LEVEL=DEBUG
```

С `DEBUG` в логе видно полное сообщение, которое уходит в модель: список элементов должен
совпадать с тем, что на экране (папки раскрыты/закрыты правильно, нет лишних строк).
Что ещё проверить — раздел 6 в [AUDIT.md](AUDIT.md). После проверки верните `MAX_STEPS=80`
и `LOG_LEVEL=INFO`.

## Если что-то не так

| Симптом | Что сделать |
|---|---|
| `Конфигурация некорректна: OPENAI_API_KEY пуст` | Впишите ключ в `.env` (файл именно `.env`, не `.env.example`) |
| Страница в окне слишком мелкая или крупная | Нажмите в окне `Ctrl+0` — это сбрасывает масштаб браузера (он запоминается в профиле) |
| «Не защищено» в адресной строке | Браузер не доверяет сертификату сайта (так бывает с сертификатами российских удостоверяющих центров). Агент открывает такие сайты намеренно, на работу это не влияет |
| `Не удалось открыть TARGET_URL … сайт с таким адресом не найден` | В `TARGET_URL` неверный адрес. Впишите в `.env` адрес из адресной строки своего браузера. Окно при этом не закрывается — адрес можно ввести вручную |
| `python` не найден (Windows) | Переустановите Python с галочкой «Add to PATH» или используйте `py` вместо `python` |
| Не скачивается браузер на шаге 3 | `BROWSER_CHANNEL=chrome` в `.env` (нужен установленный Google Chrome) |
| Задание открыто, но в логе `Целевой фрейм не найден. Доступные: [...]` | В скобках — адреса фреймов страницы. Часть адреса фрейма с заданием добавьте в `FRAME_KEYWORDS` |
| `LLM API ошибка` 401/403 | Проверьте ключ и баланс ProxyAPI, адрес `OPENAI_BASE_URL` |
| Агент выбирает не то или видит дерево неправильно | Запустите с `LOG_LEVEL=DEBUG`, сохраните лог и HTML одной ветки дерева |

## Файлы проекта

| Нужны для работы | Назначение |
|---|---|
| `main.py` | точка входа |
| `agent.py` | главный цикл агента |
| `dom_parser.py` | снимок страницы задания |
| `browser_controller.py` | браузер, клики, ввод |
| `openrouter_connector.py` | запросы к LLM, системный промпт |
| `task_memory.py` | память по заданию |
| `recorder.py` | режим записи (`--record`) |
| `models.py`, `config.py` | модели данных и настройки |
| `requirements.txt`, `.env` | зависимости и ваши настройки |

Необязательные: `tests/` (самопроверка), `requirements-dev.txt`, `pytest.ini`, `AUDIT.md`,
`.env.example` (образец настроек), `.gitignore`. Файлы, начинающиеся с точки, в macOS Finder
скрыты — показать: `Cmd+Shift+.`
