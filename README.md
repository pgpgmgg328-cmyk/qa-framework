# T-Work агент v4

Автономный агент для заданий на платформе T-Work: Playwright управляет браузером,
LLM через OpenRouter решает задания. Модель можно задать одну или «лестницей» — от
дешёвой к сильной: каждый вид заданий агент решает самой дешёвой моделью, которая справляется с ним
в тренировке (см. «Лестница моделей»). Агент не привязан
к одному виду заданий. Модель получает страницу задания целиком: текст, таблицы, ссылки, фото, расшифровку
аудио, поля формы, инструкцию к заказу и разборы прошлых ошибок. Дальше она сама решает, что делать:
выбрать ответ, заполнить поле, поискать в интернете, исправить ответ после «Неверный ответ».
Агент решает задания заказа подряд. Когда платформа вернёт на список заказов, агент пишет итог
заказа и **ждёт следующий заказ** — браузер остаётся открытым.

Что изменено и почему — в [AUDIT.md](AUDIT.md) (раздел 0 — v4).

## Что умеет

| Вид задания (из записи) | Что делает агент |
|---|---|
| Сравнение карточек (отели) | Читает поля обеих карточек и смотрит все фото (коллажи с номерами). Сам считает расстояние между точками из ссылок «Открыть карту» |
| Характеристика товара | Видит название, описание, таблицу характеристик и предразметку. Знает подпись списка («Цвет»), открывает список и выбирает значение |
| Фото банкомата / клининг | Скачивает все фото в исходном качестве. Видит, к какому варианту относится каждый блок фото. Для проверки качества и полноты съёмки (все ли поверхности сняты, не обрезаны ли) отправляет фото по одному, а не коллажем |
| Звонок робота | Скачивает запись; Gemini её слушает, расшифровывает и отмечает, кто отвечал: живой человек или автоответчик (в том числе голосовой помощник или «секретарь», который звучит как человек и спрашивает «что вы хотите?», «из какого вы банка?»), и где робот не понял ответ. Модель, которая решает задание, тоже слушает запись сама. Дослушивает запись до конца перед отправкой; если за это время вы сами поменяли ответ в окне — отправляет ваш. Без расшифровки ответ не угадывает — просит человека |
| Поиск организации | Ищет в отдельной вкладке (Яндекс Карты, Otzovik, поисковик), открывает карточки, копирует адрес и ID |
| Тесты, деревья категорий | Отвечает на все вопросы формы, раскрывает ветки дерева |
| Инструкция к заказу | Читает её один раз (и подсказки «?» у вариантов) — из диалога, из вкладки (дожидается, пока текст загрузится) или из PDF (его переписывает модель, схемы и деревья решений — текстом целиком), сохраняет в `knowledge/` и передаёт модели в каждом задании этого вида |
| Тренировка | После «Неверный ответ» читает подсказку, исправляет ответ и записывает разбор ошибки: что было в задании, какие ответы неверны, подсказку и верный ответ |

Агент никогда не нажимает «Выйти из задания», «Завершить смену» и похожие кнопки. На вопрос
«Выйти из задания?» он отвечает «Нет, остаться». Окна новостей сайта закрывает сам.

## Что нужно заранее

- **Python 3.10–3.14** (проверено на 3.10, 3.11, 3.13, 3.14). Для Windows: при установке с python.org
  отметьте «Add python.exe to PATH».
- **Ключ OpenRouter** (openrouter.ai → Keys) и деньги на балансе OpenRouter.
- Интернет для установки пакетов и браузера (≈150 МБ).

## Установка (один раз)

Все команды выполняются **в папке проекта** (там, где лежит `main.py`).
Команды для Windows даны для PowerShell или cmd; для macOS/Linux — отдельной строкой.
Если вы ставите пакеты без виртуального окружения (в общий Python), вместо
`.venv\Scripts\python` пишите просто `python`.

**1. Виртуальное окружение**

```
python -m venv .venv
```
(macOS/Linux: `python3 -m venv .venv`; если на Windows несколько версий Python — `py -3.11 -m venv .venv`)

**2. Пакеты**

```
.venv\Scripts\python -m pip install -r requirements-dev.txt
```
(macOS/Linux: `.venv/bin/python -m pip install -r requirements-dev.txt`)

`requirements-dev.txt` = пакеты агента + pytest для самопроверки. Без тестов хватит `requirements.txt`.

**3. Браузер для Playwright**

```
.venv\Scripts\python -m playwright install chromium
```
(macOS/Linux: `.venv/bin/python -m playwright install chromium`)

Если загрузка браузера не проходит, можно использовать уже установленный Google Chrome:
пропустите этот шаг и впишите в `.env` строку `BROWSER_CHANNEL=chrome`.

**4. Настройки**

```
copy .env.example .env
notepad .env
```
(macOS/Linux: `cp .env.example .env` и откройте `.env` в любом редакторе)

В `.env` проверьте две строки:

- `TARGET_URL=` — адрес страницы, с которой вы начинаете работу с заданиями. По умолчанию
  `https://twork.tbank.ru`; если вы начинаете с другой страницы — скопируйте её адрес из
  адресной строки браузера.
- `OPENROUTER_API_KEY=` — ключ OpenRouter (openrouter.ai → Keys → Create Key). Для режима
  записи (`--record`) он не нужен. Там же, у ключа, задайте лимит расходов (Credit limit) —
  OpenRouter не даст потратить больше, а агент будет писать в логе, сколько осталось.

Остальное уже настроено:
лестница моделей Gemini 3.1 Flash-Lite → gpt-5.4-mini, окно браузера видно (`HEADLESS=false`),
логин сохраняется в папке `.browser-profile` (`USER_DATA_DIR`).

**5. Самопроверка (рекомендуется, ключ не тратится)**

```
.venv\Scripts\python -m pytest
```
(macOS/Linux: `.venv/bin/python -m pytest`)

Ожидаемый итог: `124 passed, 1 skipped`. Тесты запускают браузер на локальных тестовых страницах
(в том числе на копии структуры заданий T-Work с вымышленными данными) и проверяют парсер,
фото, аудио, поиск, инструкции, тренировку с ошибкой и остановку на списке заказов. К T-Work и
к LLM тесты не обращаются.

### Обновление с v3

Если у вас уже есть `.env` от прошлой версии, удалите или исправьте в нём строки:

```
MAX_STEPS=80            → удалить (иначе агент остановится после 80 действий)
MAX_STEPS_PER_TASK=30   → удалить
LLM_VISION=image        → LLM_VISION=auto
LLM_VISION_DETAIL=low   → LLM_VISION_DETAIL=high
LLM_MAX_TOKENS=1024     → LLM_MAX_TOKENS=2000
```

Проще всего заново скопировать `.env.example` в `.env` и вписать ключ. При старых значениях
агент сам напишет предупреждение в логе.

### Обновление с v4.x

Распакуйте новую версию поверх старой папки (`.env`, `.browser-profile` и `knowledge` не
затрагиваются). С v4.5 агент работает **только через OpenRouter**. В `.env`:

- ключ OpenRouter — в строке `OPENROUTER_API_KEY=` (старое имя `OPENAI_API_KEY` тоже читается);
- строки `OPENAI_BASE_URL`, `LLM_PRICE`, `LLM_PRICE_CURRENCY` удалите — они больше не нужны
  (агент напомнит о них в логе);
- строку `LLM_MODEL` замените на `LLM_MODEL=google/gemini-3.1-flash-lite,openai/gpt-5.4-mini`
  (или удалите — это значение по умолчанию). Названия без поставщика (`gpt-5.4-mini`) агент
  дополняет сам: `openai/gpt-5.4-mini`.

С v4.6 выполните ещё раз команду из шага 2 установки (`pip install -r requirements-dev.txt`) —
добавился пакет для прокси (см. «OpenRouter не пускает запросы»).

С v4.8 в `.env` ничего менять не нужно: строки `EXAM_MIN_ACCURACY=0.8` и `LADDER_MIN_TASKS=3` из
прежнего образца агент считает старыми значениями по умолчанию и берёт новые — 70% и 5 заданий.
Хотите другую планку экзамена — впишите её, например `EXAM_MIN_ACCURACY=0.75`. Инструкции, которые
агент раньше прочитал из PDF во вкладке, он один раз перечитает (схемы в них были записаны одной
строкой) — в логе: «Инструкция … перечитана: было … симв., стало …».

## Запуск

```
.venv\Scripts\python main.py
```
(macOS/Linux: `.venv/bin/python main.py`)

1. Открывается окно Chromium на весь экран со страницей T-Work.
2. При первом запуске **войдите в аккаунт** в этом окне (вход сохраняется в `.browser-profile`).
3. Откройте список заказов (Клекс) и нажмите **«Приступить»** у нужного заказа. Какой заказ
   делать, выбираете вы: сам «Приступить» агент не нажимает. Дальше всё делает агент — в том
   числе нажимает «Начать» в окне «Тренировка».
4. Агент читает инструкцию к заказу и решает задания одно за другим. В логе появятся строки
   `СМЕНА ЗАДАНИЯ`, `📘 Инструкция … сохранена`, `LLM решение`, `WEB: …`, `АУДИО 1 расшифровано`,
   `✅ ЗАДАНИЕ ОТПРАВЛЕНО`, `❌ Платформа: неверный ответ` (в тренировке).
5. Когда задания заказа закончатся и платформа вернёт на список заказов, агент напишет
   `ИТОГ ЗАКАЗА` (заданий, ошибок, время, токены и стоимость) и будет ждать: откройте следующий
   заказ — агент продолжит сам. Браузер не закрывается.
6. Пока агент работает, не кликайте в его окне.

**Окно браузера можно сворачивать** (Windows). Свёрнутый Chrome не отрисовывает страницу, и агент
в нём работал бы в разы медленнее, поэтому свёрнутое окно агент сам убирает за край экрана — для
вас оно просто исчезает, а агент продолжает на полной скорости. Вернуть окно — кнопка браузера на
панели задач (или Alt+Tab). На macOS и Linux окно лучше не сворачивать, а просто перекрыть другими
окнами — агент напишет в логе, если окно свёрнуто.

**Закончить работу:** закройте окно браузера или нажмите `Ctrl+C` в терминале.

**Лог** каждого запуска сохраняется в папке `logs` (например, `logs/agent-20260927-101500.log`).

**Капча:** если она появилась на сайте или во вкладке поиска, решите её в окне браузера.
Агент ждёт до 10 минут.

### База знаний (папка `knowledge`)

Для каждого вида заданий агент ведёт файл `knowledge/<название>-<код>.md`:

- **Инструкция** — текст «Подробной инструкции» или инструкции к заказу;
- **Пояснения к вариантам** — подсказки «?» у вариантов ответа;
- **Уроки из тренировки** — разборы ошибок: «Задание: что в нём было (как его увидела модель).
  Неверно: …. Подсказка платформы: …. Верный ответ: …». Модель применяет разбор только к
  похожим заданиям. Ответ, который вы сами поменяли в окне, тоже становится разбором («Человек
  поправил ответ на …»). Уроки прежних версий вида «ответ X — неверно» без самого задания и без
  подсказки модель больше не получает: их она применяла ко всем заданиям подряд;
- **Статистика тренировки** — сколько ответов верны с первого раза, какие ответы оказывались
  правильными (модель видит это для калибровки), результаты экзаменов; с лестницей моделей — какой
  моделью агент решает этот вид (`текущая модель`) и точность каждой модели;
- **Заметки** — ваши правила для этого вида заданий. Агент их не меняет и передаёт модели
  в каждом таком задании. Строка `Модель агента: openai/gpt-5.4-mini` в заметках закрепляет
  модель для этого вида заданий — лестница его больше не трогает.

Файл `knowledge/_general.md` (создайте его сами, если нужно) модель получает во всех заданиях.
Пример: «Если фото не загрузилось, считай, что его нет». Файлы можно править между запусками.
В них тексты заданий платформы, поэтому папка не попадает в git.

### Настройки v4 (в `.env`)

| Параметр | По умолчанию | Что делает |
|---|---|---|
| `LLM_VISION` | `auto` | фото задания модели: `auto` — все фото, `frame` — скриншот, `off` — без фото |
| `LLM_VISION_DETAIL` | `high` | качество фото для модели (`low` дешевле, но мелкие детали теряются) |
| `TRANSCRIBE_MODELS` | `google/gemini-3.1-flash-lite,openai/gpt-4o-transcribe,openai/whisper-1` | модели расшифровки аудио по порядку: Gemini слушает запись сама, остальные — запасные |
| `AUDIO_TO_MODEL` | `true` | модель, которая решает задание и умеет слушать (Gemini), получает и саму запись звонка, а не только расшифровку (минута звонка ≈ $0,001) |
| `AUDIO_PLAY_TO_END` | `true` | дослушивать запись до конца перед отправкой ответа |
| `WEB_RESEARCH` | `true` | разрешить поиск в интернете |
| `SEARCH_URL` | `https://yandex.ru/search/?text={query}` | поисковик для запросов модели |
| `READ_INSTRUCTIONS` / `READ_TOOLTIPS` | `true` | читать инструкцию и подсказки «?» один раз для вида заданий |
| `EXAM_MIN_ACCURACY` / `EXAM_MIN_TASKS` | `0.7` / `3` | экзамен после тренировки агент начинает, только если в тренировке с первого раза верно не меньше 70% (решает по тренировке из 3+ заданий); `0` — не проверять |
| `VISION_DETAIL_MAX` | `16` | проверка по фото (клининг, грязь, дефекты, все ли поверхности сняты): до стольких фото — по одному, в хорошем разрешении |
| `KNOWLEDGE_PROMPT_CHARS` | `14000` | знания о виде заданий в каждом запросе, символов: инструкция целиком и свежие разборы ошибок (на них — не меньше 3500) |
| `CLOSE_BROWSER_WHEN_DONE` | `false` | `true` — после заказа сразу завершить работу (как в v4); `false` — ждать следующий заказ |
| `WINDOW_GUARD` | `true` | Windows: свёрнутое окно браузера убирать за край экрана, чтобы агент не тормозил |
| `BATCH_ACTIONS` | `true` | несколько действий за один ответ модели (меньше вызовов и токенов) |
| `LLM_MODEL` | `google/gemini-3.1-flash-lite,openai/gpt-5.4-mini` | модель или лестница моделей через запятую, см. «Лестница моделей» |
| `LADDER_MIN_ACCURACY` / `LADDER_MIN_TASKS` | `0.8` / `5` | лестница: вид заданий переходит к следующей модели, если в тренировке с первого раза верно меньше 80% ответов (решение — по 5 заданиям или раньше, если 80% уже не набрать); модель, к которой перешли, решает не меньше 5 заданий, прежде чем агент сравнит её с прежней |
| `LLM_REASONING_EFFORT` | `auto` | `auto` — без «обдумывания» (быстро и дёшево), `low` / `medium` — точнее, но «обдумывание» оплачивается как ответ |
| `LLM_CHECK_MODEL` / `LLM_CHECK_BELOW` | — / `0.7` | перепроверка: если модель не уверена в ответе (ниже порога), который отправляет, решение перепроверяет модель `LLM_CHECK_MODEL` |
| `LLM_PROXY` | — | прокси только для запросов к OpenRouter, например `socks5://127.0.0.1:10808` (см. «OpenRouter не пускает запросы») |
| `LLM_OUTAGE_WAIT` | `300` | OpenRouter недоступен (блокировка, нет связи, нет денег): сколько секунд ждать и повторять запрос на одном шаге |
| `LOG_DIR` | `logs` | папка логов (пусто — без файла) |

### Тренировка и экзамен

Обычно заказ из вкладки «Обучение» — это тренировка с подсказками, а за ней экзамен без подсказок:
деньги и доступ к заданиям дают, только если экзамен сдан. Поэтому агент:

- считает, сколько ответов тренировки верны **с первого раза**, и пишет это в `ИТОГ ЗАКАЗА` и в файл
  вида заданий в `knowledge/`;
- **не начинает экзамен**, если в тренировке с первого раза верно меньше 70% (или ошибок уже
  столько, что 70% из 3 заданий не набрать): в логе будет
  `⛔ ЭКЗАМЕН НЕ НАЧИНАЮ …`, агент ждёт и не тратит токены. Экзамен можно пройти самому (агент не
  мешает) или поставить `EXAM_MIN_ACCURACY=0`, чтобы агент решал его сам. Планка — 70%, а не 80%:
  к концу тренировки у агента накапливаются разборы ошибок, и отвечает он точнее, чем в её начале;
- распознаёт окно «Экзамен не пройден / пройден»: пишет `❌ ЭКЗАМЕН НЕ ПРОЙДЕН` или
  `✅ ЭКЗАМЕН ПРОЙДЕН`, запоминает итог и закрывает окно сам.

Тренировка — дешёвая проверка, справляется ли агент с этим видом заданий: если точность низкая,
этот вид лучше делать самому. С лестницей моделей тренировка ещё и выбирает модель: экзамен решает
та модель, на которой агент остановился, и порог считается по её ответам — но пока у неё мало
заданий, оценка подтягивается к точности всей тренировки (2 из 3 у модели при 17 из 22 во всей
тренировке — это ≈ 73%, а не 66%). Не сдан экзамен — следующий заказ этого вида агент решает
следующей моделью.

После двух неверных ответов на одно задание платформа принимает любой третий — поэтому такой ответ
агент не считает правильным: в разборе ошибки он помечен «принят, но верен ли он, не известно».

### Лестница моделей

Самый большой расход — цена модели. Лестница выбирает под каждый вид заданий самую дешёвую модель,
которая с ним справляется:

1. в `.env` перечислены модели через запятую — от дешёвой к сильной;
2. новый вид заданий агент начинает **самой дешёвой** моделью;
3. в тренировке (там ошибка ничего не стоит — платформа говорит «Неверный ответ» и даёт исправить)
   агент считает, сколько ответов модель дала верно с первого раза. Если меньше 80% — вид
   переходит к следующей модели: в логе `📈 Вид «…»: модель … не справляется (…) — дальше этот
   вид решает …`. Решение — по 5 заданиям (одна ошибка из пяти — ещё 80%) или раньше, если 80%
   уже не набрать (две ошибки в первых заданиях);
4. модель, к которой перешли, решает не меньше 5 заданий. Если и она ниже 80%, агент возвращает
   ту, что точнее (`📉 … точнее не стала`): сильная модель не всегда точнее дешёвой. Прежде это
   решалось по одному-трём заданиям, и модели «прыгали» туда-обратно;
5. выбор хранится в `knowledge/` — в следующих заказах этого вида агент сразу берёт нужную модель.
   Экзамен и обычные задания решает выбранная модель. Не сдан экзамен — следующий заказ этого вида
   решает следующая модель.

По умолчанию:

| Модель | $ за 1 млн токенов (вход / выход) | Чем хороша |
|---|---|---|
| `google/gemini-3.1-flash-lite` | 0,25 / 1,50 | в 3 раза дешевле gpt-5.4-mini; хорошо понимает фото (тест MMMU-Pro — 76,8%), но слабее в рассуждениях |
| `openai/gpt-5.4-mini` | 0,75 / 4,50 | сильнее в рассуждениях и поиске — для видов, где Flash-Lite ошибается |

Проба дешёвой модели почти ничего не стоит: одна-две ошибки тренировки на вид заданий, доли цента,
и только один раз — дальше агент помнит выбор. Если дешёвая модель не справится ни с одним видом,
расход будет таким же, как с одной gpt-5.4-mini, но не больше.

**Как проверить, что лестница работает.** При запуске агент проверяет каждую модель лестницы и
пишет её цену и цену фото. В шапке каждого шага и в `ИТОГ ЗАКАЗА` видно, какой моделью решается
задание, а в файле вида заданий в `knowledge/` — статистика каждой модели.

**Закрепить модель вручную.** Если вы знаете, что вид заданий по силам только сильной модели
(или, наоборот, хватает дешёвой), впишите в раздел «Заметки» его файла в `knowledge/` строку
`Модель агента: openai/gpt-5.4-mini`. Название с опечаткой агент заметит: решит задание первой
моделью лестницы и напишет об этом в логе. Модель лестницы, которую OpenRouter перестал
предоставлять, агент при запуске убирает из лестницы (`⚠ … Убираю её из лестницы`) и работает
остальными.

### OpenRouter не пускает запросы (403 «Access denied by security policy»)

Если в логе `🚫 OpenRouter не пускает запросы с этого компьютера: 403 «Access denied by security
policy»` — запрос остановила защита Cloudflare перед OpenRouter. Ключ, баланс и модели ни при чём:
запрос до OpenRouter просто не дошёл. Так бывает, когда запрос уходит из России без VPN (или VPN
работает только в браузере), либо когда адрес VPN-сервера попал в «подозрительные».

Что делает агент: не пропускает задание и не тратит на него шаги — ждёт и повторяет запрос (сначала
через 5 секунд, дальше реже, до минуты), пишет в лог раз в 5 минут, что всё ещё ждёт, а когда связь
вернулась — `✅ OpenRouter снова отвечает — продолжаю`. Если блокировка уже на запуске — агент
через полминуты остановится с объяснением.

Что сделать вам — один из вариантов:

1. **VPN для всех программ.** Включите в VPN-клиенте режим, в котором через VPN идёт весь трафик
   компьютера («TUN», «системный VPN», «весь трафик»), а не только браузер. Если ошибка осталась —
   выберите другой сервер VPN.
2. **Прокси только для OpenRouter** — если T-Work через VPN не открывается. Большинство VPN-клиентов
   (v2rayN, Hiddify, Nekoray, Clash и др.) открывают на компьютере локальный прокси — его адрес и
   порт есть в настройках клиента («SOCKS-порт» / «HTTP-порт» / «Локальный прокси»). Впишите его в
   `.env`, например `LLM_PROXY=socks5://127.0.0.1:10808` (или `http://127.0.0.1:10809`). Тогда
   запросы к OpenRouter идут через VPN, а браузер с T-Work — напрямую. VPN при этом включать для
   всего компьютера не нужно, но клиент должен быть запущен.

### Расход и стоимость

OpenRouter берёт с вас цену поставщика модели без наценки (комиссия 5,5% — только при пополнении
баланса картой). «Обдумывание» моделей агент выключает: у Gemini и gpt-5 оно включено по умолчанию
и оплачивается как ответ.

**Сколько стоит заказ** (оценка по логу реальных заказов из «Обучения»):

| Заказ | gpt-5.4-mini | Gemini 3.1 Flash-Lite |
|---|---|---|
| Проверка качества по фото (≈ 20 заданий, фото осматриваются по одному) | ≈ $0,20–0,25 | ≈ $0,07–0,09 |
| Поиск данных организаций (≈ 7 заданий, поиск в интернете) | ≈ $0,20–0,25 | ≈ $0,07–0,08 |
| Простые задания без фото (≈ 20 заданий) | ≈ $0,08 | ≈ $0,03 |

На $14 (≈ $15 минус комиссия) хватит примерно на 55–70 заказов, если все виды заданий уйдут на
gpt-5.4-mini, и на 150–200 — если все останутся на Gemini 3.1 Flash-Lite. Реально — где-то между:
какие виды заданий справится решать дешёвая модель, покажет тренировка.

По логу одного дня (8 заказов, 124 задания, почти всё — Gemini 3.1 Flash-Lite): ≈ $0,46 за всё.
Звонки (экзамен, 7 заданий) — $0,025; «Выберите задание» (21) — $0,05; «Проверка ID устройства» (24)
— $0,05; оттенки товаров (31) — $0,07; дороже всего — «Тип и категория звонка» (20 заданий) — $0,12:
много ошибок, а каждое исправление — ещё вызов модели.

**Где смотреть расход.** При запуске: `Ключ OpenRouter: потрачено всего …, сегодня …; лимит ключа
…, осталось …`. После каждого задания — `Токены на задание …`, после заказа — `ИТОГ ЗАКАЗА … ≈ $… ;
на ключе OpenRouter осталось ≈ $… — примерно на N таких заказов`, в конце работы — `ТОКЕНЫ за
запуск`. Стоимость — точная, её сообщает OpenRouter. Остаток и «на сколько заказов хватит» агент
пишет, если у ключа задан лимит расходов (openrouter.ai → Keys → ключ → Credit limit) — задайте его,
например, равным балансу: тогда и OpenRouter не даст потратить больше.

**Кончились деньги.** В логе `💳 OpenRouter отказал в оплате …` — пополните баланс или поднимите
лимит ключа: агент ждёт и продолжит сам.

**Проверка модели при запуске.** Перед работой агент делает по два крошечных запроса к каждой модели
и пишет, например: `Модель google/gemini-3.1-flash-lite: доступна, ответ за 0.8 с; фото 512×512 —
… токенов на вход (≈ $…); цена за 1 млн токенов: вход $0.25, выход $1.5`. Если модель считает фото
аномально дорого, в логе будет `⚠ Модель … считает фото очень дорого` — тогда выберите другую.

**Задания с проверкой по фото** (клининг, грязь, дефекты, все ли поверхности банкомата сняты)
дороже остальных: мелкие детали (пыль, остатки скотча, обрезанная панель, неверный ракурс) на
коллаже не видны, поэтому такие фото уходят модели по одному, в хорошем разрешении, и модель
осматривает каждое фото отдельно (у Gemini — около $0,001 на задание дороже коллажа).

Расшифровка звонков: Gemini 3.1 Flash-Lite слушает запись в обычном запросе — доли цента за минуту;
запасные `openai/gpt-4o-transcribe` — $0,006/мин, `openai/gpt-4o-mini-transcribe` — $0,003/мин.
Модель, которая решает задание, тоже получает запись (если умеет слушать): ≈ $0,001 за минуту звонка
на вызов. Выключить — `AUDIO_TO_MODEL=false`.
Инструкция в PDF переписывается моделью один раз для вида заданий — около цента.

Что ещё агент делает, чтобы тратить меньше (точность от этого не страдает):

- **Пакет действий.** Модель за один ответ отмечает ответы на все вопросы и отправляет.
  Агент выполняет действия по одному и проверяет каждое; если появилось новое поле или что-то
  пошло не так — останавливается до отправки. Выключить: `BATCH_ACTIONS=false`.
- **Кэш.** Всё, что не меняется внутри задания (инструкция, советы, фото, расшифровка), стоит
  в начале запроса, и повторные вызовы оплачиваются по цене кэша (у gpt-5.4 и Gemini 3 — 10% цены).
- **Короткий системный промпт и короткие ответы модели.** Советы по фото, аудио, картам, спискам
  и поиску модель получает только там, где они нужны.
- **Коллажи фото по 774 px** вместо 1030 px: модели считают токены по площади картинки, а деталей
  больше не становится.
- **Ожидание без вызовов.** Если модель решила подождать (загрузка), следующий вызов — когда
  страница изменится, а не каждые пару секунд.

## Режим записи (для настройки агента под новые виды заданий)

```
.venv\Scripts\python main.py --record
```
(macOS/Linux: `.venv/bin/python main.py --record`)

В этом режиме агент **ничего не нажимает** и ключ API не нужен. Вы проходите задания вручную
в открывшемся окне, а агент на каждом новом экране сохраняет:

- HTML страницы задания и скриншот окна;
- то, что он отправил бы модели на этом экране (`llm_view.txt`);
- ваши действия: клики, выбор вариантов, введённый текст, Enter;
- переходы в других вкладках (поиск в интернете) и скриншоты этих страниц.

В консоли видно, что запись идёт: `📸 #12 …` — новый экран, `👆 click …` — ваше действие.

Закончить запись: закройте окно браузера (или `Ctrl+C` в терминале). Всё упакуется в
`recordings\<дата-время>-part1.zip` (если данных много — несколько частей до 24 МБ).

**Как проходить задания во время записи**

- Важнее разнообразие, чем количество: в каждом виде задания/теста 2–3 задания, затем следующий вид.
- Показывайте и правильные решения, и ошибки — так видно, как платформа сообщает об ошибке.
  Намеренно ошибайтесь только там, где это безопасно: ошибки в квалификационных тестах
  могут снизить рейтинг или закрыть доступ к заданиям.
- Поиск в интернете делайте в новой вкладке **этого же окна** — тогда запишутся запросы
  и открытые страницы.
- Пояснения («здесь правильный ответ такой, потому что…») пишите текстом: в чат или в файл
  `notes.txt` рядом с архивом.

**Как отправить запись.** В архиве ваши данные (имя аккаунта, содержимое заданий), поэтому:

1. Сделайте репозиторий приватным: Settings → General → Danger Zone → Change visibility → Private.
2. На странице репозитория: Add file → Upload files → перетащите zip-части.
3. Внизу выберите «Create a new branch for this commit», назовите ветку `recordings` → Commit changes.

## Первый запуск — пробный

Для первого знакомства начните с заказа в режиме **«Тренировка»**: там ошибки не учитываются,
а платформа подсказывает правильные ответы. Агент их запомнит в `knowledge/`. Поставьте в `.env`:

```
MAX_STEPS=15
LOG_LEVEL=DEBUG
```

С `DEBUG` в логе видно полное сообщение, которое уходит в модель: текст страницы, фото,
расшифровка, элементы. Оно должно совпадать с тем, что на экране. Что ещё проверить — раздел 0
в [AUDIT.md](AUDIT.md). После проверки удалите строку `MAX_STEPS` и верните `LOG_LEVEL=INFO`.

## Если что-то не так

| Симптом | Что сделать |
|---|---|
| `Модель … недоступна у OpenRouter` | Такой модели нет у OpenRouter (или опечатка). Впишите в `LLM_MODEL` модель со страницы openrouter.ai/models, вида `google/gemini-3.1-flash-lite` |
| `⚠ Модель … считает фото очень дорого` | Задания с фото на этой модели обойдутся дорого — выберите другую модель или поставьте `LLM_VISION_DETAIL=low` |
| `Окно браузера свёрнуто: …` (macOS, Linux) | Не сворачивайте окно, просто перекройте его другими окнами — иначе агент работает медленно |
| `Конфигурация некорректна: ключ OpenRouter не задан` | Ключ должен быть в файле `.env` после `OPENROUTER_API_KEY=` (не в `.env.example` и не в `.env.txt`, который создаёт Блокнот). В конце сообщения агент пишет, что именно не так и какую команду выполнить |
| Страница в окне слишком мелкая или крупная | Нажмите в окне `Ctrl+0` — это сбрасывает масштаб браузера (он запоминается в профиле) |
| «Не защищено» в адресной строке | Браузер не доверяет сертификату сайта (так бывает с сертификатами российских удостоверяющих центров). Агент открывает такие сайты намеренно, на работу это не влияет |
| `Не удалось открыть TARGET_URL … сайт с таким адресом не найден` | В `TARGET_URL` неверный адрес. Впишите в `.env` адрес из адресной строки своего браузера. Окно при этом не закрывается — адрес можно ввести вручную |
| `python` не найден (Windows) | Переустановите Python с галочкой «Add to PATH» или используйте `py` вместо `python` |
| Не скачивается браузер на шаге 3 | `BROWSER_CHANNEL=chrome` в `.env` (нужен установленный Google Chrome) |
| Задание открыто, но в логе `Целевой фрейм не найден. Доступные: [...]` | В скобках — адреса фреймов страницы. Часть адреса фрейма с заданием добавьте в `FRAME_KEYWORDS` |
| `Ключ OpenRouter не подходит` или `LLM API ошибка` 401 | Проверьте ключ в `OPENROUTER_API_KEY` (openrouter.ai → Keys) |
| `💳 OpenRouter отказал в оплате` | Кончились деньги на балансе или лимит ключа — пополните баланс или поднимите лимит, агент продолжит сам |
| Агент выбирает не то | Запустите с `LOG_LEVEL=DEBUG`: в логе полное сообщение модели (что она «видит»). Правило для этого вида заданий можно дописать в раздел «Заметки» файла в `knowledge/` |
| `🚫 OpenRouter не пускает запросы … Access denied by security policy` | Запрос остановила защита Cloudflare (Россия без VPN или «подозрительный» VPN). См. «OpenRouter не пускает запросы»: VPN для всех программ или `LLM_PROXY` |
| `🌐 Нет связи с OpenRouter` | Проверьте интернет и VPN; агент ждёт и повторяет запрос сам |
| `Расшифровка моделью … недоступна` | OpenRouter не принял эту модель расшифровки — агент пробует следующую из `TRANSCRIBE_MODELS` |
| `👤 Пока запись доигрывала, ответ в окне поменяли` | Вы сами выбрали другой ответ, пока агент дослушивал запись: агент отправляет ваш ответ, а случай записывает в разборы ошибок (как пример для модели). Если это вышло случайно — просто не трогайте окно во время прослушивания |
| Агент путает человека и автоответчик | Модель слушает запись сама; самые показательные случаи попадают в разборы ошибок. Если путает часто — впишите в `TRANSCRIBE_MODELS` первой более сильную Gemini (например, `google/gemini-3.8-flash`, её название — на openrouter.ai/models): расшифровка станет примерно вдвое дороже, но всё ещё меньше цента за звонок |
| `⛔ ЭКЗАМЕН НЕ НАЧИНАЮ` при точности чуть ниже планки | Планка — `EXAM_MIN_ACCURACY` (по умолчанию 0.7). Экзамен можно пройти самому или поставить планку ниже; не сданный экзамен обычно не даёт денег |
| `… запись не удалось расшифровать … Нужна помощь человека` | Ни одна модель не расшифровала запись — агент не угадывает ответ. Решите задание сами, агент продолжит со следующего |
| `Инструкция открыта, но текста в ней не найдено … Вкладка: …` | В сообщении — что было на странице инструкции (тип, холсты, картинки, встроенные документы) и что скачал браузер. Пришлите эту строку; текст инструкции можно вписать вручную в раздел «Инструкция» файла в `knowledge/` |
| `WEB: сайт показал капчу` | Решите капчу во вкладке поиска — агент продолжит сам |
| Агент стоит на списке заказов | Так и задумано: выберите заказ кнопкой «Приступить». Закончить работу — закройте окно браузера |
