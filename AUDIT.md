# Аудит агента T-Work: v2 → v3

Документ описывает, что было не так в v2 (`agent.py`, `browser_controller.py`, `dom_parser.py`,
`openrouter_connector.py`, `models.py`, `config.py`, `main.py`), как это подтверждено и что изменено в v3.
Все утверждения о багах v2 проверены запуском исходного кода в Chromium 141 (Playwright 1.56)
на фикстурах из `tests/fixtures/`, а не только чтением кода.

---

## 1. Краткий аудит v2

### Что сделано хорошо
- Правильная декомпозиция: парсер → решение LLM → исполнитель, Pydantic-модели между слоями.
- Идея `target_text` для сверки индекса — верное направление против галлюцинаций.
- Физический клик с движением мыши и JS-фоллбэк; `ignore_https_errors` для сертификатов Минцифры.
- Отдельные сущности FOLDER/OPTION и состояние папки в промпте; сигнатура задания для сброса памяти.
- `response_format=json_object`, `temperature=0`, reasoning перед action (зачаток CoT).

### Главный вывод
Большая часть «галлюцинаций с индексами» — **не ошибка LLM, а детерминированные баги инфраструктуры**:
парсер и контроллер нумеровали элементы по-разному, а CSS-зум сдвигал все физические клики.
Модель называла правильный элемент, а клик уходил в другой.

### Подтверждённые дефекты v2 (воспроизведено)

| # | Дефект | Как проявляется | Серьёзность |
|---|--------|-----------------|-------------|
| 1 | Индексы парсера ≠ индексам `click_by_index` | Парсер нумерует только видимые элементы своего селектора, контроллер кликает `.nth(i)` другого селектора по всем совпадениям (скрытые `input`, `display:none`). На фикстуре дерева **9 из 10** индексов указывали на чужой элемент; «Завершить» (idx 9) кликал вариант «Смартфоны» | критично |
| 2 | `document.body.style.zoom = '75%'` | Playwright считает координаты без учёта CSS-zoom: физический клик по bbox «Завершить» попадал в пустую область, `locator.click()` падал по таймауту — и для same-origin, и для cross-origin iframe | критично |
| 3 | «Завершить смену» вместо «Завершить» | Если основная кнопка неактивна, `click_by_text("завершить")` находит подстроку в «Завершить смену» и **нажимает её** | критично |
| 4 | Стартовый флоу до LLM на каждом шаге | Подстрочный поиск «хорошо/далее/начать» по любым элементам: вариант ответа «Хорошо» нажимался 3 шага подряд, LLM не получала управление; «Далее» пропускал вопрос без ответа | критично |
| 5 | SVG-иконка валит весь парсинг | `el.className` у SVG — объект, `cls.includes` → `TypeError: cls.includes is not a function` (любая иконка с классом `*list-item*`, `*tree-item*`) | критично |
| 6 | Дети свёрнутых веток видны LLM | `isVisible` использовал `&&` вместо `\|\|` и не учитывал `overflow:hidden` схлопнутого контейнера (tui-expand, аккордеон) — модель «выбирала» невидимые варианты | высокая |
| 7 | Дубли строк | Контейнер ветки + заголовок + кнопка-стрелка + скрытый radio = 3–4 строки на одну («› Одежда», «›», …) | высокая |
| 8 | Автокоррекция уводила клик | Частичное совпадение цепляло контейнер с текстом всех детей; при дублях («Другое» в каждой папке) всегда бралось первое, даже если индекс LLM был верным; тип элемента не учитывался | высокая |
| 9 | `_banned` / `_open_counters` по индексам | После раскрытия любой папки индексы сдвигаются — запрет «переезжал» на другие строки, в т.ч. на правильный ответ | высокая |
| 10 | Нет истории действий в промпте | LLM не знала, что уже раскрывала и что не сработало → осцилляции open/close | высокая |
| 11 | Состояние папки | Раскрытость только по `aria-expanded`/классам; для кастомных деревьев любая раскрытая папка — «ЗАКРЫТА», повторный open её сворачивал | высокая |
| 12 | Ложное «✓Выбран» | `cls.includes('active')` истинно для `inactive`, `interactive`; `selected` — для `unselected` | средняя |
| 13 | Любая иконка = папка | `querySelector('tui-svg, .t-icon')` делал FOLDER из чекбоксов Taiga (галочка — `tui-svg`) и кнопок с иконкой | средняя |
| 14 | Капча по тексту body | Слово «капча» в задании или подпись reCAPTCHA → `while True` без таймаута, агент висит навсегда | средняя |
| 15 | `task_identifier` = src первого `<img>` | Логотип → память не сбрасывается между заданиями; иконка в дереве → сброс посреди задания | средняя |
| 16 | Неатомарный парсинг | ~18 последовательных CDP-вызовов: текст задания и элементы могли прийти из разных состояний DOM | средняя |
| 17 | Обрезка по порядку документа | `MAX_ELEMENTS` отрезал хвост — при большом дереве пропадала кнопка «Завершить» | средняя |
| 18 | Легенда промпта ≠ формату | Промпт описывал `[FOLDER ЗАКРЫТА]`, строки приходили как `[ПАПКА ЗАКРЫТА]` | средняя |
| 19 | Прочее | Таймаут LLM по умолчанию 600 с; `confidence=95` или `target_text=12` роняли шаг (ValidationError); `logger.warning("idx=%d …")` без аргумента; `slow_mo=80` замедлял каждый CDP-вызов; UA Chrome/124 при реальном 141; submit сбрасывал память до проверки, что задание сменилось; автосабмит при повторном клике по выбранному | низкая–средняя |

## 2. План улучшений (выполнено в v3)

1. **Стабильные метки вместо индексов** — `dom_parser.py`: каждый элемент снимка получает
   `data-agent-id="<поколение>-<номер>"`, контроллер кликает строго по метке. Перерисованный узел теряет
   метку → клик не выполняется (stale), агент делает новый снимок.
2. **Атомарный снимок одним `evaluate`** — элементы, текст задания, подсказки, ошибки, капча, лоадер,
   картинка, прокручиваемые списки. Возврат JSON-строкой: 1500 строк за ~0.15 с (было ~0.5 с).
3. **Слияние вложенных совпадений** — стрелка → `toggle` строки (`data-agent-toggle`), скрытый radio →
   `control`, контейнер без своего текста не показывается. Текст строки — без текста вложенных строк.
4. **Видимость** — `checkVisibility()` (opacity/visibility предков), обрезка `overflow:hidden`,
   открытые shadow root, перекрытие (`elementFromPoint`) → флаг ⚠ПЕРЕКРЫТ.
5. **Состояния по токенам классов, ARIA и структуре** — раскрытость папки ещё и по видимым детям;
   selected — из вложенного `input.checked`; путь `⟨Электроника › Телефоны⟩` для одинаковых названий.
6. **Клик** — `click(trial=True)` (видим, стабилен, активен, не перекрыт) → плавная мышь →
   JS-фоллбэк с `PointerEvent` + `el.click()`. Масштаб — `device_scale_factor` вместо CSS-zoom.
7. **Ожидание стабилизации DOM** (MutationObserver) вместо фиксированных `sleep`.
8. **Память по ключам** (`task_memory.py`) — «группа|путь|текст», проверка фактического эффекта
   каждого действия по следующему снимку («✓ раскрыто, появилось 3: …», «✗ без эффекта»).
9. **Промпт v3** — история с результатами, запреты по тексту, сообщения страницы, бюджет шагов,
   стратегия поиска в дереве, правила submit, пример; Structured Outputs; картинка задания (vision).
10. **Отправка с проверкой** — клик → ожидание смены отпечатка задания; при неудаче — текст ошибок
    страницы в историю. Deny-список для «Завершить смену / Выйти / Отправить на доработку».
11. **Надёжность цикла** — бюджет на задание, шаги ожидания не тратят лимит, капча с таймаутом,
    выход при закрытии браузера, адаптация к reasoning-моделям, одна попытка «ремонта» JSON.
12. **Тесты** — 34 теста: реальный Chromium, кросс-доменный iframe, масштаб 75%, фейковый
    OpenAI-совместимый сервер, сквозной прогон агента на двух заданиях.

## 3. Системный промпт v3

Полный текст — `openrouter_connector.py`, константа `SYSTEM_PROMPT`. Ключевые решения:

- **Легенда генерируется из `models.py`** (`PROMPT_LEGEND`, `PROMPT_FLAGS`) — теми же константами
  рендерятся строки элементов, расхождение формата исключено (тест `test_every_rendered_tag_is_explained…`).
- **CoT через порядок полей схемы**: `goal → observation → reasoning → action → target_*`. Модель
  сначала формулирует цель и выписывает релевантные элементы `[N] «текст»`, потом выбирает действие.
- **Правило «сначала текст, потом номер»**: найти строку по смыслу, затем переписать её номер;
  `target_text` — дословно из той же строки. Скрипт сверяет и чинит номер.
- **Стратегия дерева**: одна самая вероятная папка за шаг, от общего к частному; раскрытые не трогать;
  «Другое» — только если в правильной ветке нет конкретного варианта.
- **Правила submit**: все требования выполнены, checkbox → отметить все, неактивная кнопка = форма
  не заполнена, после неудачной отправки — читать сообщения страницы.
- **Structured Outputs** (`json_schema`, `strict`) с `enum` для `action` — невалидное действие
  физически невозможно; при отказе прокси — откат на `json_object`.

User-сообщение собирается из блоков: ЗАДАНИЕ (+картинка), ПОДСКАЗКА, СООБЩЕНИЯ СТРАНИЦЫ, СОСТОЯНИЕ
(загрузка, оверлей, прокрутка), ЭЛЕМЕНТЫ, ИСТОРИЯ, НЕ ПОВТОРЯТЬ, ВНИМАНИЕ (бюджет, петли).

Пример строк, которые видит модель:

```
[0] [FOLDER закрыта] «Одежда»
[1] [FOLDER раскрыта] «Электроника»
  [2] [OPTION radio] «Смартфоны» ✓ВЫБРАН
  [3] [OPTION radio] «Другое» ⟨путь: Электроника⟩
[4] [BUTTON] «Завершить»
```

## 4. Ключевые изменения в коде

| Файл | Что сделано |
|------|-------------|
| `dom_parser.py` | JS-снимок `_JS_SNAPSHOT`: обход shadow DOM, видимость, слияние строк, состояния, путь, метки, текст задания/подсказки/ошибки, капча, лоадер, картинка; `select_for_prompt` сохраняет кнопки при обрезке |
| `browser_controller.py` | `click_element` по метке с trial-проверкой и JS-фоллбэком; `type_into` с проверкой значения и `select_option`; `scroll` колесом; `wait_settle`; `find_target_frame` с приоритетом и проверкой размера; `page_has_captcha`; DSF-масштаб; постоянный профиль (`USER_DATA_DIR`) |
| `agent.py` | Шаг v3, `_resolve_target` (тип + дубли + индекс), `_do_submit` с проверкой смены задания, безопасный стартовый флоу, бюджет задания, капча с таймаутом, «предохранители» от вечных отказов |
| `task_memory.py` (новый) | История с фактическими результатами, запреты по ключам, проверка эффекта действий |
| `openrouter_connector.py` | Промпт v3, Structured Outputs, vision, таймауты/ретраи, адаптация к reasoning-моделям, ремонт JSON |
| `models.py` | `uid`/`key`/`path`/`value`/…, единая легенда, толерантный `LLMDecision`, `DecisionContext` |
| `config.py` | Новые параметры, `validate_config()`, списки через `.env` |

Удалён `BrowserController.click_by_index()`: клик по номеру в произвольном селекторе и был
источником бага №1. Для совместимости оставлены `get_target_frame()`, `click_by_text()`
(безопасная версия), `DomParser.get_task_identifier()`, `build_elements_prompt()`.

## 5. Запуск и тесты

```bash
pip install -r requirements-dev.txt
playwright install chromium          # если браузер ещё не установлен
cp .env.example .env                 # заполнить OPENAI_API_KEY
python main.py
python -m pytest                     # 34 теста, ~20 с, без сети и ключей
```

Рекомендуется `USER_DATA_DIR=.browser-profile`: логин в T-Work сохранится между запусками
(в v2 каждый запуск начинался с чистого профиля).

## 6. Что проверить на реальной платформе

Фикстуры повторяют известные классы T-Work (`child__header`, `child__expand`, `t-item`) и
паттерны Taiga UI, но реальный DOM я не видел. При первом запуске с `LOG_LEVEL=DEBUG`:

1. Лог `Снимок #N: элементов=…` и текст user-сообщения — нет ли дублей и лишних строк.
2. `task_id` не должен меняться при раскрытии папок. Если в логе «Отпечаток задания изменился
   только в цифрах» — в текст задания попал таймер/счётчик, сузьте `TASK_TEXT_SELECTORS`.
3. Папки `[FOLDER раскрыта/закрыта]` соответствуют экрану; если нет — пришлите HTML одной ветки.
4. Кнопка отправки находится (`FINISH_BUTTON_TEXTS`), опасные — в `FINISH_DENY_SUBSTRINGS`.
5. Если задания с картинками — включён `LLM_VISION=image`.
