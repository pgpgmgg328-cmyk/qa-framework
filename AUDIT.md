# Аудит агента T-Work: v2 → v3 → v4 (v4.9)

Раздел 0 — версия v4: разбор записи реальных заданий (режим `--record`) и что изменено, чтобы
агент решал задания ЛЮБОГО вида, а не только дерево категорий. Разделы 1–6 — аудит v2 и
изменения v3 (история).

---

## 0. v4: универсальный агент по записи реальных заданий

### Что показала запись (151 экран, 7 видов заданий)

Все задания платформы собраны из одного конструктора форм (`flex-*`, Taiga UI): компоненты
`header`, `text` (абзацы с `<br>`, таблицы, ссылки), `mediaGallery` (фото, карусели с пагинацией),
`audio` (свой плеер поверх `<audio>`), `radiobuttonGroup`, `checkbox`, `dropdownLists`
(выпадающий список в портале), `textInput` (`tui-textarea`), `horizontalComparator` (две
карточки рядом). Над формой — панель режима («Тренировка / Экзамен, N из M»), «Подробная
инструкция», подсказки платформы. Виды заданий в записи: сравнение отелей (фото + адреса +
координаты), выбор значения характеристики товара, проверка фото банкомата, оценка клининга,
поиск организации в интернете (Яндекс Карты + Otzovik), прослушивание звонка робота, список
заказов. Перед заданиями открываются инструкция к заказу и заставка тренировки; в тренировке
после ошибки платформа пишет «Неверный ответ» и часто — правильный ответ с объяснением.

### Что сделано в v4

1. **Страница целиком (reader-view)** — `dom_parser.py`: весь видимый текст по порядку документа —
   заголовки `#`, абзацы с переносами, таблицы `| … |`, ссылки с адресами (`→ https://…`),
   `[ФОТО n]`, `[АУДИО n]`, сообщения платформы (‼ ошибка, 💡 подсказка) и интерактивные элементы
   НА СВОИХ МЕСТАХ. Открытый диалог, выпадающий список и всплывающие уведомления — отдельными
   разделами. Подпись поля (`⟨поле: Цвет⟩`) — у элемента. Плеер и пагинация карусели скрыты.
2. **Отпечаток задания** без сообщений платформы, подсказок при наведении, таймеров, значений полей
   и строк раскрытых веток дерева; `TaskIdentity` в агенте отличает догрузку фото и счётчики от
   нового задания и различает задания с одинаковым текстом по фото.
3. **Фото** — `media.py`: каждое фото скачивается в исходном качестве (вложения — со страницы
   задания с её авторизацией; чужие CDN — запросом браузерного контекста), уменьшается в браузере,
   до 6 фото — по одному, больше — коллажами с крупными номерами = `[ФОТО n]`.
4. **Аудио** — запись скачивается и расшифровывается (`audio.transcriptions`, модели по очереди,
   с таймкодами), воспроизводится, а перед отправкой доигрывается до конца.
5. **Поиск в интернете** — `research.py`, действие `web`: запрос или адрес в отдельной вкладке,
   модель получает адрес страницы, текст и ссылки; ссылки на внешние сайты со страницы задания тоже
   открываются там (переход увёл бы фрейм задания).
6. **Инструкции и уроки** — `knowledge.py`, папка `knowledge/`: инструкция к виду заданий (диалог,
   вложенный документ или вкладка) и подсказки «?» читаются один раз и сохраняются; «Неверный
   ответ» + подсказка превращаются в урок; раздел «Заметки» — для правил пользователя.
7. **Тренировка** — после «Неверный ответ» задание не считается новым, модель получает ответ
   платформы, подсказку и список уже отклонённых ответов и исправляет ответ.
8. **Остановка** на списке заказов (фрейм без `/task` и кнопки «Приступить»); сам «Приступить» агент
   не нажимает. Диалог «Выйти из задания?» → «Нет, остаться». Окна новостей сайта закрываются.
9. **Системный промпт** без привязки к виду заданий: как разбирать задание, сравнивать карточки,
   смотреть фото, слушать аудио, искать в интернете, проверять форму перед отправкой, исправлять
   ответ после ошибки. В ответе модели — поле `plan` (выводы и найденные факты переносятся между
   шагами) и `query` для поиска. Скрипт сам считает расстояние между точками из ссылок на карты
   и отмечает одинаковые файлы фото.

### Экономия токенов (v4.1)

Замер токенизатором gpt-4o (o200k) на страницах из записи: постоянная часть каждого вызова была
3,1 тыс. токенов (системный промпт 2,8 тыс. + схема ответа), фото — до 3,1 тыс. токенов на вызов,
и на задание уходило 2–8 вызовов. Сделано, без потери точности:

1. **Пакет действий** (`actions`): модель за один ответ отмечает ответы на все видимые вопросы и
   отправляет. Исполнитель находит цели по снимку, который видела модель, затем перед каждым
   следующим действием снимает страницу заново и проверяет: эффект прошлого действия (✓), то же
   задание, не открылся диалог, нет новых ошибок, не появились новые поля. Иначе пакет
   останавливается до отправки, а модель получает заметку «что не выполнено и почему». Submit
   ставится только последним; после open, web и scroll нужен новый взгляд модели.
   Вызовов на задание в 2–3 раза меньше.
2. **Системный промпт 2827 → 1850 токенов**: советы для фото, аудио, сравнения карточек, списков
   значений, дерева и поиска (33–114 токенов) приходят в разделе «ПОДСКАЗКИ» только там, где на
   странице есть соответствующие элементы. Правила из v4.0 сохранены — сверено построчно.
3. **Порядок под кэш OpenAI**: неизменное внутри задания (знания, подсказки, фото, аудио) — в
   начале сообщения, страница и история — в конце.
4. **Компактный ответ**: `goal` объединён с `observation`; одно поле `value` вместо
   `type_text`/`query`/`scroll_direction`.

Попутно исправлено: поле, которое появляется после выбора ответа («Укажите причину»), раньше
меняло отпечаток задания и сбрасывало память. Теперь отпечаток считается по тексту, а состав
формы — отдельно (`TaskIdentity.form`).

Оценка на gpt-4o по видам заданий из записи: −38…68% токенов и денег на задание (таблица в
README). Счётчик в логе показывает фактический расход по данным API.

### v4.2: запуск теста, окно браузера, стоимость

По первому запуску на реальной платформе:

1. **«Начать» в окне «Тренировка» нажимал человек.** Под этим окном на T-Work ещё крутится
   загрузка задания (и не уходит, пока «Начать» не нажата). Агент сначала ждал загрузку — до ~25 с
   (5 ожиданий по ~4,5 с), и человек успевал нажать сам. Теперь стартовое окно обрабатывается до
   ожидания загрузки, первым же шагом и без модели (тест с такой же заставкой и загрузкой под ней).
2. **Браузер закрывался после заказа.** Теперь после возврата на список заказов агент пишет
   `ИТОГ ЗАКАЗА` и ждёт: человек открывает следующий заказ — агент продолжает; закрыл окно —
   агент завершается. Если агент остановился сам (простой, лимит шагов), окно тоже остаётся
   открытым. Прежнее поведение — `CLOSE_BROWSER_WHEN_DONE=true`.
3. **В свёрнутом окне агент работал медленно.** Проверено в Chromium под Xvfb с оконным
   менеджером: у свёрнутого окна нет кадров отрисовки — анимации сайта не завершаются, проверки
   Playwright перед кликом («элемент неподвижен») ждут кадра и падают по таймауту, скриншоты не
   получаются. Окно, закрытое другими окнами или стоящее за краем экрана, работает на полной
   скорости (Playwright запускает Chrome с `--disable-backgrounding-occluded-windows`).
   - Windows: `window_guard.py` — свёрнутое окно браузера разворачивается за край экрана без
     перехвата фокуса (`SW_SHOWNOACTIVATE`), выбор окна на панели задач возвращает его на место.
   - Всегда: если страница не отрисовывается (нет кадра за 250 мс), клик сразу идёт через JS, а не
     ждёт таймаутов; прокрутка — через JS; скриншот не ждётся.
   - Поиск в интернете и вкладка инструкции больше не вызывают `bring_to_front` (он активирует окно
     браузера и разворачивает свёрнутое посреди работы человека): вкладка поиска закрывается после
     чтения, и браузер сам возвращается на вкладку задания.

   Тот же заказ (заставка + 2 задания), видимое окно:

   | | окно открыто | окно свёрнуто |
   |---|---|---|
   | v4.1 | 18,2 с | 55,0 с (7 кликов по ~6 с на таймаутах) |
   | v4.2 | 13,2 с | 12,9 с |

4. **$1,5 за тест при оплате ~$0,5.** Разбор по записи: вызов gpt-4o — ~8 тыс. токенов на вход
   (системный промпт 1,9 тыс., инструкция до 2,3 тыс., фото 1–5 тыс., страница ~1 тыс.), 1–2 вызова
   на задание; 15 заданий — ~$0,55 по прайсу OpenAI, у прокси с наценкой — ~$1,2–1,5. Утечек нет,
   дорога сама модель. Сделано:
   - модель по умолчанию `gpt-5.4-mini` (≈ ¼ стоимости gpt-4o с учётом кэша за 10% цены), вариант
     `gpt-5.4-nano` (≈ 1⁄13) и перепроверка неуверенных ответов более сильной моделью
     (`LLM_CHECK_MODEL`); gpt-4.1 не предлагается — в API его отключают 14.10.2026;
   - параметры gpt-5.x сразу (`max_completion_tokens`, `reasoning_effort` с откатом none → minimal →
     low), без лишнего запроса с ошибкой;
   - проверка модели перед работой: модели нет у прокси — понятная ошибка до открытия браузера;
     сколько токенов стоит фото — в логе, аномально дорого (у gpt-5.4-mini в мае 2026 сообщали о
     ~66 тыс. токенов за скриншот) — предупреждение;
   - стоимость в логе по заданию, заказу и запуску (прайс OpenAI или свои цены в `LLM_PRICE`);
   - коллажи фото 774 px вместо 1030: gpt-4o всё равно уменьшает до 768 px (токены те же), новые
     модели считают по площади — −40% токенов за фото;
   - короткие ответы модели; после «skip» агент ждёт изменения страницы (до 8–20 с), а не зовёт
     модель каждые пару секунд;
   - лог каждого запуска — в файле `logs/…`.

### v4.3: экзамены, проверка качества по фото, поиск организаций

Разбор лога пользователя (два заказа из «Обучения», gpt-5.4-mini): оба экзамена не сданы, деньги
не начислены. Лог насчитал ≈ $0,40 по прайсу OpenAI, прокси списал ≈ $2.

- **Клининг** (20 заданий, 30 вызовов, 165 тыс. токенов): в тренировке с первого раза верно 6 из 13.
  Модель почти всегда ошибалась в одну сторону: из 7 ответов «Выполнен качественно» верным был
  1 (подсказки платформы: остатки скотча, грязь у основания фальш-двери, пыль, нет фото верхней
  панели). Фото уходили коллажами 2×2 по 774 px — на фото ~390 px, мелкие недостатки не видны;
  уроки из подсказок не помогли (та же ошибка дважды подряд). Экзамен: 5 ответов «качественно»
  из 9 → «Экзамен не пройден».
- **Данные организации** (7 заданий, 43 вызова, 480 тыс. токенов): «Организация не найдена»
  после двух неудачных запросов (поиск по Картам с «site:», подсказка v4.2 разрешала сдаться после
  2–3 запросов); не та точка на Картах (платформа: брать точку с наибольшим числом отзывов);
  в экзамене — ответ без ссылки на Карты. В каждый вызов уходил полный текст двух последних
  страниц поиска и 40 ссылок — ~11 тыс. токенов на вызов.
- Агент сам начал оба экзамена, хотя тренировка шла на ~50%.

Сделано:
- **Ворота экзамена:** точность тренировки с первого раза считается по заказу и по виду заданий
  (`knowledge/`, раздел «Статистика тренировки»); ниже `EXAM_MIN_ACCURACY` (80%) агент не нажимает
  «Начать» экзамена и не решает задания в режиме «Экзамен», а пишет почему.
- **Итог экзамена** («не пройден» / «пройден») распознаётся, пишется в лог, итог заказа и базу
  знаний; окно закрывается без модели.
- **Проверка качества по фото:** до 16 фото — по одному, 1024 px; подсказка «осмотри каждое фото по
  строке, недостатки — в том числе по краям и у основания, сверь обязательные ракурсы, не списывай
  подозрительное на блики»; в знаниях — какие ответы в тренировке были правильными (калибровка).
- **Поиск организаций:** сразу Яндекс Карты по «название + город», без операторов; «не найдено» —
  только после Карт, домена и адреса; из нескольких точек — по инструкции, иначе с наибольшим
  числом отзывов. Полностью в запрос идёт только последняя страница, у прежних — 6 главных ссылок;
  ссылок на странице — 25 вместо 40.

### v4.4: лестница моделей и OpenRouter

Задача пользователя — тратить минимум при той же отдаче. Разбор лога v4.3: почти весь расход —
вызовы gpt-5.4-mini (оба заказа: 645 тыс. токенов на вход, из них 252 тыс. из кэша, 18 тыс. на
выход — ≈ $0,39 по прайсу OpenAI). Те же токены на Gemini 2.5 Flash-Lite — ≈ $0,05–0,07, на
Gemini 3.1 Flash-Lite — ≈ $0,13–0,19. Но дешёвые модели справляются не со всеми видами заданий, а
какие виды им по силам — заранее неизвестно. Ответ даёт тренировка: там ошибка ничего не стоит.

Сделано:
- **Лестница моделей** (`LLM_MODEL=дешёвая,…,сильная`): новый вид заданий агент начинает самой
  дешёвой моделью; первые ответы тренировки записываются по моделям (`knowledge/`, «Статистика
  тренировки»). Точность ниже `LADDER_MIN_ACCURACY` (80%) по `LADDER_MIN_TASKS` (3) заданиям — вид
  переходит к следующей модели; решение принимается сразу, как только порог становится
  недостижимым (при 80% из 3 — после первой ошибки). Экзамен не сдан — тоже переход. Ворота
  экзамена считают точность той модели, которая будет решать экзамен; при малом числе заданий
  экзамен не начинается, если 80% уже не набрать.
- Модель можно закрепить за видом заданий строкой `Модель агента: …` в «Заметках» (в промпт модели
  эта строка не попадает). Недоступная закреплённая модель → задание решает первая модель
  лестницы, в логе предупреждение. Модель лестницы, которой нет у прокси при запуске (Google
  отключает Gemini 2.5 Flash-Lite около 20.10.2026), убирается из лестницы, агент работает дальше.
- **OpenRouter:** цены моделей — из его `/models` при запуске, стоимость вызова — точная, из
  `usage.cost` ответа; «обдумывание» выключается его параметром `reasoning.effort` (none → minimal
  → low, если модель не принимает); `max_completion_tokens` для gpt-5/o; непонятная ошибка 400
  (так не-OpenAI модели отвергают строгую схему ответа) → повтор с обычным JSON; расшифровка —
  моделями `openai/…` (префикс добавляется сам), без таймкодов, если прокси их не отдаёт.
- 402 (кончились деньги на балансе) — понятное сообщение в логе не чаще раза в 10 минут, агент
  ждёт и продолжает после пополнения.
- Мелкие суммы в логе видны (`$0.000026`, а не `$0.0000`).

### v4.5: только OpenRouter, расход на виду

- **ProxyAPI убран.** Адрес OpenRouter задан в коде, ключ — `OPENROUTER_API_KEY` (старое имя
  `OPENAI_API_KEY` тоже читается), названия моделей без поставщика дополняются
  (`gpt-5.4-mini` → `openai/gpt-5.4-mini`). Цены в рублях (`LLM_PRICE`) и прайс OpenAI в коде больше
  не нужны: стоимость каждого вызова сообщает OpenRouter (`usage.cost`), цены для справки — из его

- адрес задания проверяется без домена (`TASK_URL_KEYWORDS`, у Ozon — `/task/`); в главном фрейме
  агент работает только на страницах заданий — вход в Ozon ID, кабинет, статистику не трогает;
- `DIALOG_SELECTORS` — окна площадки без role="dialog": диалог для парсера, не новость для агента;
  `PAGE_SKIP_SELECTORS` — части страницы, которых модель не видит (элементы, текст, фото, сообщения);
- крестик окна без текста (класс или data-testid с close) — элемент «Закрыть», а не текст всего окна
  (общее правило парсера);
- `ORDERS_DONE_TEXTS` — экран «закончились задачи» = заказ выполнен; `POOL_URL_RE` — вид задания по
  адресу (у Ozon — проект `/task/<id>`), инструкция читается один раз на проект;
- тесты запускают браузер с `BROWSER_CHANNEL` (как агент): Chromium Playwright не скачивался — набор
  прогнан в установленном Chrome.

Проверки: `tests/fixtures/ozon_task.html`, `ozon_projects.html` — копия структуры живых страниц
(классы, data-testid, задержки появления страницы и инструкции, закреплённая панель «Отправить»),
товары вымышлены; `tests/test_ozon.py` — настройки площадки (в отдельном процессе), снимок страницы,
список проектов и экран конца, клик по варианту под панелью, агент целиком (инструкция → две страницы
→ конец проекта), ожидание на входе в Ozon ID и на списке проектов.

**Адверсариальное ревью** (саб-агент-атакующий, 6 раундов, каждая атака — скрипт с реальным выводом):
вход в Ozon ID с адресом возврата `?redirect=…/task/…` считался страницей задания (адрес теперь — только
путь); окна новостей нажимались на странице входа («Продолжить» отправило бы SMS); окно «Уведомления»
перезаписывало инструкцию проекта; проект из кабинета в новой вкладке не находился; один неверный
селектор из `.env` отключал весь список; адрес T-Work в `.env` в другом написании мешал Ozon; агент
забирал вкладку, где человек сам решает экзамен; окно входа с полями кода `type=text` уходило модели;
неполный ответ уходил по исчерпанию бюджета и по решению модели. Всё исправлено и закреплено тестами.

**Первые запуски и запись пользователя** (логи 7.10, запись 9.10: 346 экранов, ~15 проектов, все вкладки):
- *ложная «смена задания»*: в «цены по фото» ответ «Да» открывает новые вопросы — агент считал страницу
  новым заданием, бросал начатый ответ и звал модель заново (15 отправок — 44 «смены»). Теперь, пока
  ответ не отправлен, страница, где прежний текст весь на месте, — то же задание (на записи: 33 → 4);
- *неверный ответ в тренировке*: Ozon оставляет задание и показывает уведомление «Ошибка — Для отправки
  ответа необходимо решить все задания». Парсер брал контейнер уведомлений (`hint`), а `warning` стоит
  на вложенной плашке; вид уведомления теперь — и по вложенным классам, закреплённое на экране — `toast`.
  `WRONG_ANSWER_TEXTS` площадки → «неверный ответ»: разбор ошибки, ответ не повторяется;
- *фото*: под каруселью Ozon полоса миниатюр со всеми фото, слайды карусели браузер рисует лишь первые

- «Пропустить 0/10» — в стоп-список Ozon (`EXTRA_DENY_SUBSTRINGS`);
- рекордер пишет вкладку, которую видит человек (проекты из кабинета, поиск), а не только первую;
- задания с рамкой на фото («Демо: разметка изображений») агент не умеет — рисовать мышью нечем.

6. **Клик** — `click(trial=True)` (видим, стабилен, активен, не перекрыт) → плавная мышь →

8. **Память по ключам** (`task_memory.py`) — «группа|путь|текст», проверка фактического эффекта

9. **Промпт v3** — история с результатами, запреты по тексту, сообщения страницы, бюджет шагов,

## 3. Системный промпт v3

Полный текст — `openrouter_connector.py`, константа `SYSTEM_PROMPT`. Ключевые решения:

- **Легенда генерируется из `models.py`** (`PROMPT_LEGEND`, `PROMPT_FLAGS`) — теми же константами
  рендерятся строки элементов, расхождение формата исключено (тест `test_every_rendered_tag_is_explained…`).
- **CoT через порядок полей схемы**: `goal → observation → reasoning → action → target_*`. Модель
  сначала формулирует цель и выписывает релевантные элементы `[N] «текст»`, потом выбирает действие.
- **Правило «сначала текст, потом номер»**: найти строку по смыслу, затем переписать её номер;
  `target_text` — дословно из той же строки. Скрипт сверяет и чинит номер.
- **Стратегия дерева**: одна самая вероятная папка за шаг, от общего к частному; раскрытые не трогать;
  «Другое» — только если в правильной ветке нет конкретного варианта.
- **Правила submit**: все требования выполнены, checkbox → отметить все, неактивная кнопка = форма
  не заполнена, после неудачной отправки — читать сообщения страницы.
- **Structured Outputs** (`json_schema`, `strict`) с `enum` для `action` — невалидное действие
  физически невозможно; при отказе прокси — откат на `json_object`.

User-сообщение собирается из блоков: ЗАДАНИЕ (+картинка), ПОДСКАЗКА, СООБЩЕНИЯ СТРАНИЦЫ, СОСТОЯНИЕ
(загрузка, оверлей, прокрутка), ЭЛЕМЕНТЫ, ИСТОРИЯ, НЕ ПОВТОРЯТЬ, ВНИМАНИЕ (бюджет, петли).

Пример строк, которые видит модель:

```
[0] [FOLDER закрыта] «Одежда»
[1] [FOLDER раскрыта] «Электроника»
  [2] [OPTION radio] «Смартфоны» ✓ВЫБРАН
  [3] [OPTION radio] «Другое» ⟨путь: Электроника⟩
[4] [BUTTON] «Завершить»
```
